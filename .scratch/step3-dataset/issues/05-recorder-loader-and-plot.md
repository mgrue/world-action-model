## Question

What module, API and commands deliver the dataset, and what proves it correct?

- Module layout: `toycar.dataset` (record, load, windows) — no torch dependency in the core; a thin optional PyTorch `Dataset` wrapper, or leave that to Step 4/6?
- Recorder CLI: `python -m toycar.dataset record --out DIR …` with parallel workers; resumable; deterministic regardless of worker count; writes a manifest (versions, params, seed ranges, counts, hashes).
- Loader API: open a dataset, list episodes per split, get a window by index, iterate windows; returns numpy arrays with the shapes fixed by ticket 04.
- Verification: replay check (re-simulate an episode from its metadata and compare States/Frames), dataset stats (Instruction/Direction balance, branch split, perturbed fraction, speed histogram).
- PLAN check tool: `python -m toycar.dataset plot` showing one window — observed Frame, the 16 future Frames in a strip, the action traces (steer/throttle, clean vs executed), with tick indices so alignment is visible. Output PNG (matplotlib as a dev/optional dependency?) or a pygame viewer?

Check: an API and CLI sketch with signatures, the manifest fields, the list of automated tests, and the manual acceptance steps.

## Comments
- Q1 module layout → one new module **`toycar.dataset`**, numpy only; **no torch anywhere in `toycar`**. The loader's `Windows` has `__len__`/`__getitem__(i)` returning a dict of numpy arrays and scalars (ticket 04 fields), which PyTorch's `DataLoader` uses directly (default collate), so no wrapper is needed. Model code (Step 4+) lives outside `toycar`, depends on it and adds torch.
- Q2 on-disk layout → `data/<name>/` (default `step3-v1`, `--out` overrides; `data/` gitignored). Contents: `manifest.json` plus `train.npz`, `val.npz`, `test.npz`, each with stacked uncompressed arrays: `states` (E, T+1, 4) f64, `clean`/`executed` (E, T, 2) f32, `perturbed` (E, T) bool, `station_m` (E, T+1) f32, `branch` (E, T+1) i8, `planned_branch` (E, T) i8, plus the per-episode table (`k`, `seed`, `instruction`, `direction`, `start_route`, `length`, `render_params` (E, 5, 3) u8, `frames_sha256`). About 16 KB per episode, about 100 MB total, loaded fully into RAM. Recorder: no resume (under a minute); writes to `data/<name>.tmp/` and renames on success; refuses to overwrite without `--force`; parallel, with output identical for any `--workers`.
- Q3 manifest and check on open → `manifest.json` carries: `format_version: 1`; provenance (`toycar_version`, Python/numpy versions, platform, `git_commit` + `dirty` if available, SHA-256 of `render.py`/`track.py`/`physics.py`/`expert.py` sources, creation time); recipe (T, per-split counts and seed blocks, `ExpertParams`, `TrackParams`, default `RenderParams`, jitter ranges and stream id, start-spec and `k mod 6` rules); summary (episodes, ticks, usable windows per split at H = 16 with the filter, `any` outer fraction, perturbed share). **On open:** re-render 4 seeded random episodes per split and compare `frames_sha256`; a mismatch **raises** naming the episode. A code-hash mismatch only **warns** (source changes needn't change output; the frame check is authoritative). `verify` checks every episode; `check=False` skips the check.
- Q4 loader API → `record(out, *, episodes={"train": 4800, "val": 600, "test": 600}, length=300, workers=None, force=False)`; `open_dataset(path, *, check=True) -> Dataset` (`manifest`, `split(name) -> EpisodeSet`, `verify()`); `EpisodeSet` (`__len__`, `episode(i)`, `frames(i, ticks=None, probe=None)`, `windows(*, horizon=16, future_frames=None, clean_future=True, probe=None) -> Windows`, `eval_subset(n=2048, **window_kwargs)`); `Windows` (`__len__`, `__getitem__ -> dict`, arrays `index` (N, 2) int32, `approaches_section`, `in_section`); `PROBES`; `frame_dataset(es)` for Step 4 (every Frame as one item). `probe=` accepts colour probes only (`wide_fork` needs new driving and is rejected).
- Q5 CLI and plot → `python -m toycar.dataset record [--out data/step3-v1] [--workers K] [--force]`, `verify [DIR]`, `stats [DIR]` (episodes and usable windows per split × Instruction × Direction, `any` outer fraction, perturbed share, `approaches_section` share, speed histogram), `plot [DIR] [--split val] [--episode I --t T | --seed N] [--approaching] [--probe NAME] [--out window.png]`. The plot PNG shows fₜ then future Frames labelled `k=0 (t+1)` … `k=15 (t+16)`, with steer/throttle per k (clean solid, executed dashed, perturbed shaded) and v from States in the same columns, so action k sits directly under the Frame it causes; the title gives split, episode, seed, t, Instruction, Direction and `approaches_section`. matplotlib lives in a new `viz` dependency group (`uv run --group viz …`); core and tests don't need it.
- Q6 tests and acceptance → pytest on small datasets in `tmp_path` (e.g. 12/6/6 episodes × 60 ticks): `test_record_layout`, `test_record_workers_identical`, `test_record_atomic_and_force`, `test_crash_aborts`, `test_episode_replays`, `test_window_alignment` (obs = render(sₜ); future k = render(sₜ₊₁₊ₖ) = render(step_state(sₜ₊ₖ, executedₜ₊ₖ)); actions k = cleanₜ₊ₖ), `test_clean_future_filter` (vs brute force, H = 16 and 8), `test_future_frames_subset`, `test_hash_check` (tampered params raise; code-hash change warns), `test_eval_subset_fixed`, `test_colour_jitter`, `test_probes`, `test_dataloader_compat` (skip without torch), `test_cli` (plot skipped without matplotlib). **Manual acceptance:** (1) full `record` in about a minute, about 100 MB; `stats` shows 6000 episodes, about 0.98M usable windows, about 50% outer under `any`; (2) `verify` passes; (3) PLAN check: `plot` several windows, including `--approaching` under `any` and `--probe brown_grass`, and future Frame k shows the effect of the action in column k; (4) `uv run pytest` passes for Steps 1–3.

**Resolution (2026-11-03):**
- **Module:** `toycar.dataset`, numpy only; no torch in `toycar`. `Windows` is directly usable by PyTorch's `DataLoader`.
- **Disk:** `data/<name>/` (gitignored; default `step3-v1`) = `manifest.json` + `train.npz`/`val.npz`/`test.npz` of stacked uncompressed per-tick arrays and the per-episode table; about 100 MB, loaded into RAM. Atomic write via `.tmp` + rename, `--force` to overwrite, no resume, output independent of `--workers`.
- **Manifest:** format version, provenance (versions, git commit/dirty, source hashes of render/track/physics/expert), full recipe, summary counts. On open, 4 seeded episodes per split are re-rendered and hash-checked (mismatch raises); a code-hash change warns; `verify` checks everything.
- **API:** `record`, `open_dataset → Dataset.split → EpisodeSet.windows / eval_subset / frames / episode`, `Windows` (index + `approaches_section`/`in_section` arrays), `PROBES`, `frame_dataset` for Step 4.
- **CLI:** `record`, `verify`, `stats`, `plot` (matplotlib in a `viz` dependency group); the plot puts action k directly under future Frame k.
- **Tests and acceptance:** as in Q6.
